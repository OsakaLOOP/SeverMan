# 运行与部署标准

## 基准与度量

基准为 2 vCPU、4 GB 内存、3 Mbps 公网出口；该规格来自最新需求文件。4 vCPU 的主机使用相同预算，增加 CPU 余量。少于 200 名用户、典型并发 5。下列数字是项目验收目标，组件性能以目标主机实测为准。

常规负载采用 5 个并发客户端，总计 10 请求/秒持续 30 分钟：60% 分页读取、20% 写入、10% 跨站快照、10% 会话或任务查询。登录和外部调用单独测量。突发测试 20 并发、30 请求/秒、5 分钟，观察限流和恢复，不要求突发响应达到常规延迟。

主要业务表使用至少 10 万条、用户范围和索引接近实际的数据。数据库热缓存和首次访问分别记录。整机测试包含所有拟常驻服务，压测工具在其他机器运行。

## 内存与 CPU

| 组件 | 正常占用目标 | 初始容器上限 |
|---|---:|---:|
| PostgreSQL | 450–650 MiB | 768 MiB |
| core-api，含认证 | 150–300 MiB | 512 MiB |
| core-worker | 80–150 MiB | 256 MiB |
| 6 个业务/辅助服务 | 每个 60–120 MiB | 每个 192 MiB，共 1152 MiB |
| Caddy | 30–70 MiB | 128 MiB |
| 轻量观测 | 20–40 MiB | 64 MiB |
| 按需备份 | 100–200 MiB | 256 MiB |

容器内存上限合计 3136 MiB，为系统、Docker、内核及不可回收开销保留约 960 MiB。监控容器实际计费内存和宿主机 `MemAvailable`，正常运行维持至少 512 MiB 可用，备份期间至少 256 MiB。单个组件无法达到预算时调整同机服务数量或扩容，按实际服务数重新求和。

core-api 的 V8 old-space 初始 256 MiB，业务进程 96 MiB，worker 128 MiB；堆限制与进程总内存分别控制。单进程常驻，CPU 密集工作并发 1，普通 worker 并发 2。正常整机 CPU 15 分钟均值低于 60%，超出 80% 持续 5 分钟告警；CPU 百分比以整机两核总容量为 100%。

core-api、数据库的初始 CPU 上限各 1.5 核，worker 0.5 核；上限允许总和超过两核以利用空闲资源，正常容量仍按整机测量。后台任务通过并发和低 CPU 权重降低争用。生产构建在 CI 完成。

## 数据库与连接

PostgreSQL 初始 `shared_buffers=128MB`、`work_mem=2MB`、`maintenance_work_mem=64MB`、`effective_cache_size=1GB`、`max_connections=40`。`effective_cache_size` 是优化器估计，`work_mem` 可能按多个执行节点分配。保留 autovacuum 和默认持久化保证。

| 使用方 | 最大连接 |
|---|---:|
| 认证池 | 3 |
| 中心业务池 | 3 |
| 中心只读池 | 2 |
| worker，包括 pg-boss 内部与监听连接 | 5 |
| 6 个业务服务 | 每个 2，共 12 |
| 迁移、备份和观测 | 4 |
| 总计 | 29 |

上线核对每个库的真实默认连接数，覆盖 pg-boss 内置 pool、监听连接及发布时的重叠实例。保留 11 个连接用于管理和短期重叠；服务的认证适配器和 ORM 共用已规划的池。EdgeOne Function 通过 HTTPS 调用 Node.js API。

初始连接获取超时 1 秒，闲置连接 30 秒回收，普通 SQL 超时 1 秒、写 SQL 2 秒、锁等待 300 ms、闲置事务 2 秒。迁移和备份采用独立超时。正常池等待 p95 小于 20 ms，单条常规 SQL p95 小于 20 ms，超过 100 ms 的语句单独分析。

## 响应与带宽

| 指标 | 常规负载目标 |
|---|---|
| Node.js 普通 API | p95 ≤ 150 ms，p99 ≤ 500 ms |
| 跨站快照聚合 | p95 ≤ 300 ms，p99 ≤ 1 秒 |
| 本地令牌验证 | p95 ≤ 5 ms，不包含公钥首次下载 |
| Node.js OIDC 本地处理 | p95 ≤ 250 ms，外部身份提供方延迟另记 |
| 任务持久化受理 | p95 ≤ 100 ms |
| 无积压的高优先级任务启动 | p95 ≤ 1 秒 |
| 事件循环延迟 | p99 ≤ 50 ms |
| 常规请求服务端错误 | 小于 0.1%，授权拒绝和计划限流单独统计 |
| 公网常规 API | 在主要用户地域 p95 ≤ 1 秒，包含 Function 和网络 |

常规 JSON 响应压缩后目标不超过 8 KiB，常规请求正文上限 256 KiB。10 请求/秒、8 KiB 响应约占 0.66 Mbps，连接、TLS、其他响应和备份单独计入出口总量。3 Mbps 理论上限为 375 kB/s，整机常规出口目标低于 1.5 Mbps。

分页超大响应通过减少字段、页大小或异步导出处理。文件直传 OSS，图片处理使用云服务。短数据不重复压缩，动态 JSON 在网关压缩一次，敏感认证响应禁用缓存。CPU、延迟和出口流量共同验收。

## 外部组件

| 组件 | 性能和可靠性标准 |
|---|---|
| Better Auth | 复用 PostgreSQL 连接；Cookie 会话缓存配置服从 60 秒撤销要求；密码验证并发受限 |
| `openid-client` / `jose` | 复用 discovery 和 JWKS 缓存；并发未知 key 刷新合并并限流；外部请求超时有界 |
| EdgeOne Function | 只做轻量同源转发/聚合，单次最多 3 个并行后端调用；全部请求 5 秒截止，任务等待至多 2 秒 |
| EdgeOne 包体 | 项目压缩与打包体积按平台口径测量，目标低于 1 MB；现场验证 Web Crypto、Cookie 和 redirect |
| PostgreSQL / pg-boss | 使用规划连接池；启动 worker 数量固定；有任务时短轮询、空闲退避，队列 SQL 时间纳入数据库指标 |
| Nodemailer | `pool=true`、`maxConnections=1`，有界 SMTP 超时；队列负责重试，客户端内部无限重排关闭 |
| OSS SDK | SDK 仅加载实际厂商；凭据缓存与轮换；签名通常本地完成，远程凭据获取单独测量 |
| GitHub / SMTP / 支付 | 分别记录连接、首次响应和整体耗时；网络失败有界重试，重复副作用由幂等控制 |
| Caddy | 长连接复用、合理连接超时、访问日志轮转；只信任已配置反向代理来源 |
| pg_dump / restic | 一次只执行一组备份，限速并验证退出码；数据正确性和恢复时间同时验收 |

官方 EdgeOne 页面列有 5 MB 代码包、1 MB 请求正文、200 ms CPU 时间限制 [C08]。本项目采用更低预算；发布时核对具体产品和账号限制。用户身份和数据库状态使用源站权威数据。

## 部署规范

使用 Ubuntu LTS、Docker Compose v2、Debian slim Node.js 镜像。数据库镜像固定 PostgreSQL 主版本、补丁版本和 digest；容器非 root 运行，应用只读根目录、临时目录 tmpfs、`no-new-privileges`、移除多余 capability。

基础设施 Compose 管理数据库和入口，各仓库 Compose 管理自己的服务。数据库仅在指定 Docker 网络访问；主机公网只开放 80/443 与受限 SSH。每个服务独立数据库凭据，生产迁移使用独立账号。中心和业务容器不挂载 Docker socket。

每个服务提供不访问数据库的存活检查和验证依赖的就绪检查，依赖故障返回 503。启动迁移作为发布步骤，迁移失败停止发布；多个迁移进程使用数据库 advisory lock 互斥。长 DDL 设置锁等待上限，升级视图先提供兼容版本，再升级消费者。

SIGTERM 后停止接收新请求，最多 10 秒处理在途请求，随后关闭连接；worker 的停止等待按任务超时配置。Compose `stop_grace_period` 至少 20 秒。单实例发布允许短暂维护窗口；同库迁移优先向后兼容，回滚前评估 schema 兼容性。

## 备份与运维

每 30 分钟生成数据库一致逻辑备份，包含全部业务 schema、操作记录和队列状态，再用 restic 加密上传异地。角色定义、迁移、配置和密钥独立备份。任务恢复后依据幂等结果继续处理。备份账号和密钥不存储在公开仓库。

目标 RPO ≤ 1 小时，RTO ≤ 1 小时；以最近成功上传的备份时间衡量 RPO。初始备份上传限速 128 KiB/s，20 分钟可传约 150 MiB；每次实际新增传输目标 ≤ 100 MiB。备份超过 20 分钟或最近成功时间超过 45 分钟告警。增长后改用受控 WAL 归档备份或提升带宽，继续按目标验证。

恢复测试计时覆盖取回镜像、配置和备份、恢复数据库及检查服务；按可保证的下载吞吐计算最大可恢复数据量。首次全量备份在业务上线前完成。保留最近 48 小时、14 个日备份、8 个周备份，每月演练恢复。

初期日志总额限定 1 GiB，默认保留 7 天，禁止记录 Cookie、Authorization、密码、验证码和完整支付载荷。磁盘可用低于 20% 告警。常规请求无需对每次会话读取额外写一条审计记录；权限变更、服务配置和敏感操作持久化审计。

首期运行目标为月度可用率 99.5%，单机维护和故障计入指标。外部支付或邮件不可用时保留任务并公开状态；数据库故障时写接口停止接受成功承诺。故障演练包含数据库停止、worker 中止、SMTP 超时、连接池耗尽和磁盘空间不足。
