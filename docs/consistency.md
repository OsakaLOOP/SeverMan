# 数据一致性与任务标准

## 一致性的定义

| 场景 | 保证 | 实现 |
|---|---|---|
| 单站读写 | 已提交数据、原子更新 | 普通事务；乐观版本或必要行锁 |
| 多站资料查询 | 同一数据库快照 | 单连接 `REPEATABLE READ READ ONLY` |
| 某次异步修改后的查询 | 读到该修改或更新的已提交版本 | 等待指定操作完成，再创建读取快照 |
| 跨站多步操作 | 可追踪的进度、重试和部分失败 | pg-boss、操作依赖、业务幂等 |
| 余额、配额、订阅权益约束 | 相关变更原子完成 | 同一业务所有者在同一事务执行 |

PostgreSQL 的 MVCC 允许读写并行，写操作仍存在行锁、死锁和事务冲突。快照代表事务开始读取时的已提交状态；事务开始后的其他提交由后续查询事务读取。默认 `READ COMMITTED` 的多条 SQL 可以看到不同快照，跨站聚合显式提升隔离级别 [C16]。

## 快照读取

1. 验证用户、服务 scope 和所需数据资源。
2. 若请求携带 `after_operation_id`，先检查操作归属，等待其全部必要业务步骤完成提交。
3. 从专用只读池取得一个连接，执行 `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY`。
4. 在该连接读取全部授权视图，使用参数化用户条件；完成后提交并归还连接。
5. 返回结果和 `observed_at`。业务需要版本检查时同时返回各资源版本，时间戳本身不作为版本号。

等待任务期间不占用数据库连接或保持读取事务。对多个独立服务发 HTTP 请求属于多次观测；要求同一快照的查询统一由中心数据库读取模块执行。pg-boss 可执行较重的异步报告，执行报告时仍使用同一快照事务。

快照查询目标总时长不超过 500 ms，初始语句超时 1 秒、闲置事务超时 2 秒。列表翻页默认各页独立快照；需要整份固定快照的导出改为单次后台导出任务，并在结果中记录生成时点。

## 操作与队列

业务操作使用独立 `operation_id`，其下保存步骤、任务 ID、发起用户、服务、幂等键、请求摘要、依赖关系、重试次数和业务提交结果。操作状态由业务提交证据确定，队列状态用于调度。

状态包括 `pending`、`running`、`succeeded`、`failed`、`partially_failed`、`cancel_requested`、`cancelled`。仅当所有必要步骤提交成功后设置 `succeeded`；通知邮件等可选步骤可单独失败。依赖任务失败时，下游保持阻断并标明原因。

同库提交操作记录和任务时，通过 pg-boss 支持的事务适配器共享同一事务 [C17]。每个服务的队列 schema/账号限制到所属队列数据；中心 worker 通过受限业务命令调用站点，站点保留写入权限。

跨 HTTP 执行采用以下确认流程：站点在同一事务内完成业务修改并保存幂等结果，提交后响应 `operation_id`、步骤 ID 和资源版本。worker 收到成功结果后记录步骤完成。响应丢失时，worker 用相同幂等键查询或重试，取得已有结果。队列重试不能产生重复扣款、重复创建或重复授权。

pg-boss 的任务领取和提交能力不覆盖外部服务副作用。邮件发送成功后进程中止可能导致重发；邮件带稳定 Message-ID，支付调用使用提供方幂等键和事件去重。允许重复通知的操作明确记录该性质。

首期 worker 并发 2，普通远程任务执行超时 10 秒，重试最多 5 次，指数退避加随机偏移，总任务截止时间初始 15 分钟。认证邮件优先，维护任务低优先。参数按任务类型配置；支付和长维护任务有各自明确截止时间。

## 等待与失败

提交返回 `202`、操作 ID、状态地址和 `Retry-After`。客户端可请求最多 2 秒同步等待，完成后返回最终结果；等待截止返回 `202`，任务继续执行。轮询初始 1 秒，逐步延长到 5 秒，页面后台暂停；状态查询不能无限增加队列任务。

等待指定操作的必要步骤，范围由业务定义；全队列排空与某个用户请求无关。任务领取后的进程退出由队列过期与重试机制恢复。取消属于请求，已经提交的步骤通过业务补偿处理并公开部分结果。

对跨服务多步操作，单个快照可能看到部分已经提交的步骤。需要对所有读者同时发布的业务状态，应由一个所有者在同一事务内更新；若业务采用草稿与发布版本，则所有读取契约统一按发布版本过滤。只有等待本次操作的调用者具备本次完成后的读取保证。

## 验收

- 两个跨站查询之间并发提交更新，返回数据仍属于同一快照。
- 等待步骤提交后开启新快照，可见对应修改；提交失败不会返回成功。
- 在业务提交后、响应前中止进程，再次执行返回同一结果，业务修改次数为一。
- 多次重复提交、不同用户查询操作、依赖失败、任务取消和超时均返回对应状态。
- 中心只读账号无法修改业务表，未授权站点和认证凭据不可读。
- 对死锁或 `40001` 事务冲突，只重试具备幂等性且无未确认外部副作用的完整事务。
