# 统一身份与服务中心需求

## 已确认范围

系统服务于少于 200 名用户，典型并发约 5。现有业务主要是 EdgeOne Pages 上的 Vite/React 前端，配套 Function 与 KV，身份和用户数据分散在各站点。新系统负责统一登录、内部账号、外部身份关联、子站服务注册和管理面板，并支持现有站点逐步迁移。

站点使用多级子域名、少量独立域名及 bucket 域名。用户公开注册，内部账号是稳定身份；GitHub 优先接入，邮件服务用于注册、验证、恢复和通知。没有团队协作和审批流，保留单一 admin 能力。个别站点可利用后续提供的 SDK，嵌入自定义登录组件。

数据库采用 PostgreSQL。各站点保留独立数据模型，在同一业务数据库中使用独立 schema、角色和迁移文件。中心按授权读取站点提供的视图，业务写入由对应站点的权限完成。跨站查询使用主库同一连接中的只读事务，获得一致快照。

异步操作采用持久化任务队列；读取依赖某次操作时，先等待其必要任务提交，再开启读取事务。任务状态与错误必须可查询。业务数据保持单一来源，完成条件和等待策略见[一致性标准](consistency.md)。

首期重点是 SSO、身份模型和统一服务模型。后续接入分页 CRUD、JSON API、Webhook、邮件管理、OSS 直传、图片处理、评论、RSS、状态面板、支付网关和订阅。

## 非功能要求

- 低资源开支，符合 2 vCPU、4 GB 内存、3 Mbps 公网带宽的约束。
- 面向 Pages、Function、浏览器和 Node.js 服务保持高兼容性。
- 各站点可以独立部署、升级和停机，共同使用的数据库实例统一维护。
- API 记录用户、服务、权限、请求 ID 和错误，日志限定个人信息范围。
- 目标恢复点为 1 小时，目标恢复时间为 1 小时，数据库和密钥均需有异地备份。
- 性能与可用性按[运行与部署标准](operations.md)验收。
